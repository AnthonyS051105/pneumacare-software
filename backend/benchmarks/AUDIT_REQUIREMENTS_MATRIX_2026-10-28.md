# Matriks audit requirement feat/ai-integration — 28 Oktober 2026

## Kesimpulan

**Belum dapat dinyatakan seluruhnya sesuai atau aman untuk merge tanpa penyelesaian temuan penghambat.** Fondasi produk, dua role, penerimaan sensor, model service terpisah dan keluaran dua kelas sesuai arah demo terbaru. Perubahan AST **normal/abnormal** merupakan keputusan eksplisit Tony dan bukan bug. Persetujuan model dua kelas tidak otomatis menyetujui perubahan satuan waktu tren, penanganan kualitas vital, atau pemilihan status pasien.

Audit ini membandingkan dokumen root `docs/` dengan checkout **`.worktrees/feat-ai-integration-demo`** pada branch `feat/ai-integration`, base `b177a81` ditambah perbaikan lokal saat inspeksi. Semua path kode di bawah relatif terhadap checkout tersebut. Ini audit requirement/source read-only; tidak menjalankan tes main, tidak mengakses secrets/.env, tidak mengubah aplikasi, tidak menguji model AST asli atau perangkat fisik baru. Bukti tes dan temuan reproduksi root/backend/frontend dicatat dalam laporan gabungan oleh agen utama.

Status: **terimplementasi** = ada jalur kode yang sesuai, bukan jaminan validasi klinis; **parsial** = sebagian requirement dipenuhi; **ditunda** = dokumen memang menunda; **penghambat** = bug/perilaku yang merusak kemampuan wajib atau keamanan interpretasi; **pengecualian disetujui** = keputusan terbaru menggantikan spesifikasi model lama. Kekurangan bukti eksternal dibedakan dari bug kode.

## Pisahkan penghambat kode dari batas produk

**Penghambat kode yang perlu diputuskan/diselesaikan sebelum merge aman dalam arti permintaan Tony:** threshold pasien diabaikan pada penetapan significant; status pasien tidak mengikuti alert aktif tertinggi/level1; kualitas vital yang disimpan dapat dipakai lagi tanpa gate kualitas/umur; upgrade default terhadap DB lama tidak terlindungi. Agen utama menggabungkan bukti reproduksi dan skenario regression untuk prioritas akhir. Payload MQTT malformed juga perlu hardening agar callback satu pesan tidak mematikan jalur PPG.

**Batas produk/validasi yang tidak otomatis berarti seluruh branch harus dibuang:** RR belum ada dan sumbernya masih terbuka di SDD; kalibrasi SpO2 dan angka klinis belum final; per-siklus mengubah unit tren; skema persistence device versus channel belum diputuskan; checkpoint AST dan cache/env offline belum tersedia; kapasitas nyata dan kontinuitas ESP belum terbukti. Perubahan model dua kelas tetap sah.

**Hal yang sudah diperbaiki pada patch latest, jangan dilaporkan ulang seolah belum:** inferensi sinkron di receiver, partial digabung lintas gap, seq tidak melihat ring loss (v2 firmware/backend tersedia), cleanup hanya channel terakhir, mock otomatis saat service gagal, duplicate-current persistence, validator respons AST nonfinite/range/class mismatch, close WebSocket bytes, timestamp pre-NTP dan half-open cleanup.
